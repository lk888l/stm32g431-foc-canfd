# CANopen 通信与运动控制协议

本文描述本工程固件实际实现的通信、启动、校准、参数保存及运动控制行为。协议栈为 CANopenNode v4.1，使用经典 CANopen 服务并扩展长 PDO 到 CAN-FD。完整索引、类型、默认值和映射权限见 [对象字典](object-dictionary.md) 与 [EDS](../config/rollercan.eds)；本文说明对象的使用顺序与控制语义。

固件有五种运动模式：单圈位置、多圈位置、速度、力矩和 MIT。MIT 支持非压缩、压缩两种指令格式，共用模式值 5；模式 0 表示不运行。本实现采用 CiA 402 风格状态机，但不是完整 CiA 402 或 CiA 1301 实现；不提供 USDO、插补缓存、模式 7/8，也不接受原厂私有 29 位 CAN 命令。

| `0x6060` 模式值 | 控制方式 | 主目标对象 |
|---|---|---|
| -1（线上 `0xFF`） | 单圈最短路径位置 | `0x607A`，配合控制字 bit4/bit6 |
| 1 | 多圈累计位置 | `0x607A`，配合控制字 bit4/bit6 |
| 3 | 速度 | `0x60FF` |
| 4 | 力矩 | `0x6071` |
| 5 | MIT | 非压缩 `0x2003` 或压缩 `0x2004` |

## 1. 总线、编码与基础服务

### 1.1 默认总线参数

| 项目 | 默认值 / 行为 |
|---|---|
| Node-ID | 1，可设为 1～127 |
| 仲裁段 | 1 Mbit/s；经典 CAN 帧全程使用此速率 |
| FD 数据段 | 5 Mbit/s，FD 发送启用 BRS |
| CAN ID | 11 位标准 ID，不接受扩展 ID 或 RTR |
| SDO、NMT、SYNC、Heartbeat、EMCY | 经典 CAN 帧 |
| PDO | 映射总长 ≤8 B 用经典帧，9～64 B 用 FD+BRS；最多 16 项映射 |
| 初始 NMT 状态 | Pre-operational，心跳状态字节 `0x7F` |
| 初始驱动状态 | Switch-on disabled；控制字、模式和运动目标不从 Flash 恢复 |

5 Mbit/s 指 FD 数据段，不是经典 CAN 波特率。发送长 FD 帧时，总线上其他控制器须支持或容忍 CAN-FD；仅使用传统 CAN 2.0 主站时，所有已启用 PDO 应保持 ≤8 B。经典 SDO 不会使传统控制器自动兼容长 FD 帧。

以下示例在工程根目录执行，使用 `can0`、Node-ID=1。新设备或默认配置设备可这样配置 Linux / WSL 接口；已有保存配置时使用设备当前速率：

```sh
sudo ip link set can0 down
sudo ip link set can0 type can bitrate 1000000 sample-point 0.8 dbitrate 5000000 dsample-point 0.75 fd on
sudo ip link set can0 up
python3 tools/rollercan_cli.py --interface can0 --node 1 inspect
```

CLI 使用 Linux SocketCAN，无额外 Python 包依赖。全局选项 `--interface`、`--node` 应写在子命令之前。`inspect` 只读取状态，不使能电机。

### 1.2 数据类型与单位

多字节数值均为 **little endian**。`f32` 是 IEEE 754 Float32；`i8/i16/i32` 为有符号整数，`u8/u16/u32` 为无符号整数。对象以 `索引:子索引` 表示，变量对象的子索引为 0。不能把本工程的位置对象按整数脉冲数写入。

| 数据 | 对象示例 | 类型 / 单位 |
|---|---|---|
| 位置 | `0x607A:00`、`0x6064:00`、`0x2003:01` | f32，rev（机械圈） |
| 速度 | `0x60FF:00`、`0x606C:00`、`0x2003:02` | f32，rev/s |
| 加减速度 | `0x6083:00`、`0x6084:00`、`0x6085:00` | f32，rev/s² |
| 非压缩 MIT 前馈力矩 | `0x2003:03` | f32，Nm |
| 力矩模式目标 / 反馈 | `0x6071:00` / `0x6077:00` | i16，配置电流上限的千分比 |
| 电流反馈 | `0x2200:01～03`、`0x2203:01～02` | i32，mA |
| 母线电压 | `0x2202:00` | i32，mV |
| MCU 温度 | `0x2100:09` | i16，0.1 °C |

浮点写入必须为有限值，NaN、Infinity 和超范围值会被拒绝。位置、速度已按校准方向修正。`0x6064` 始终报告本次上电期间的软件累计位置，不随单圈模式取模；重启不保留圈数，也不把当前位置自动设为零。编码器故障后重新同步可能丢失完整圈数，主站应重新建立位置参考。固件没有单独的回零模式；极大累计圈数下 Float32 分辨率会降低。

### 1.3 服务与 NMT

以下 `N` 是当前有效 Node-ID，PDO ID 可另行配置。

| 服务 | CAN ID | 载荷 / 用途 |
|---|---|---|
| NMT | `0x000` | 2 B：命令、目标节点；节点 0 表示广播 |
| SDO 请求 / 回复 | `0x600+N` / `0x580+N` | 8 B，读写对象字典 |
| SYNC | 默认 `0x080` | 默认无计数器，发送 0 B 经典帧；固件为 consumer |
| EMCY | 默认 `0x080+N` | 8 B，CANopen 错误码、错误寄存器和错误信息 |
| Boot-up / Heartbeat | `0x700+N` | 1 B：`00` 启动、`04` stopped、`05` operational、`7F` pre-operational |

Heartbeat producer 周期 `0x1017:00` 为 u16 ms，默认 1000，0 关闭周期心跳。Boot-up 表示协议栈已启动，不表示已经校准或使能。

| NMT 命令 | 名称 | 效果 |
|---|---|---|
| `0x01` | Start | 进入 Operational，允许 PDO 处理；仍需驱动使能握手 |
| `0x02` | Stop | 退出运行并关桥，停止 SDO/PDO 服务；NMT 和心跳仍可用 |
| `0x80` | Pre-operational | 关桥，允许 SDO 配置，PDO 不参与运动控制 |
| `0x81` | Reset Node | 整机复位，加载已保存参数 |
| `0x82` | Reset Communication | 本实现也执行整机复位，不仅重启通信栈 |

Node 1 的 Start 为 ID `0x000`、数据 `01 01`；Pre-operational 为 `80 01`。NMT 无 SDO 式确认，应通过心跳和状态字确认效果。**NMT Stop 后要读状态或复位故障，应先发送 Pre-operational 恢复 SDO 服务。**

### 1.4 SDO 读写

运动与配置标量使用 expedited SDO。协议栈也提供 segmented server，附带 CLI 只使用 expedited 标量操作。

| 操作 | 字节 0 | 字节 1～3 | 字节 4～7 |
|---|---|---|---|
| 读请求 | `40` | 索引低字节、索引高字节、子索引 | 0 |
| 写 1 / 2 / 4 B 请求 | `2F` / `2B` / `23` | 同上 | 小端数据，不足 4 B 补 0 |
| 写成功回复 | `60` | 回显索引和子索引 | 0 |
| 读 1 / 2 / 4 B 回复 | `4F` / `4B` / `43` | 回显索引和子索引 | 数据 |
| Abort 回复 | `80` | 回显索引和子索引 | u32 小端 abort code |

Node 1 写控制字 0：`0x601#2B40600000000000`；读故障：`0x601#403F600000000000`。SDO 确认表示对象写入成功，实际状态由控制环随后更新，仍需读 `0x6041` 等待。

```sh
python3 tools/rollercan_cli.py read 0x6041 0 u16
python3 tools/rollercan_cli.py read 0x603f 0 u16
python3 tools/rollercan_cli.py write 0x6040 0 u16 0
```

## 2. 完整初始化与启动流程

### 2.1 固件上电流程

1. 初始化 MCU 时钟和外设，保持 PB2 功率桥使能为低。
2. 初始化对象字典，验证并恢复 Flash 校准、通信、PDO 和运动限值；无有效记录时使用默认值。运行控制字、模式和目标保持默认零值。
3. 启动板级驱动和 CANopen，应用保存的节点号与位时序，发送 Boot-up 并进入 Pre-operational。
4. 准备首个编码器 DMA 事务并启动 20 kHz PWM/ADC DMA 采样；后续每个 PWM 周期起点启动 SSC DMA，与同周期电流采样汇合后执行控制。在关桥状态采集 1024 个样本建立电流零点，采样部分约 51.2 ms；检查编码器、电源及驱动状态。运动环为 1 kHz，CANopen 任务周期 1 ms。
5. 有有效电角校准时 `0x2100:02=4`；否则等待主站显式请求校准。固件不会自行校准或恢复运动。

不能只依据心跳发送运行指令。主站还应读取故障、状态字和校准状态；电流零点尚未完成时校准请求会被拒绝。

### 2.2 主站启动顺序

| 步骤 | 动作 | 完成条件 |
|---|---|---|
| 1. 建立通信 | 按当前速率连接，等 Boot-up/心跳，读 `0x1000`、`0x1018` | 节点可用；设备类型 `0x1000=0x00020192` |
| 2. 撤销旧许可 | NMT Pre-operational，写 `0x6040=0` | `status & 0x006F = 0x0040`；若 fault 先按第 9 节恢复 |
| 3. 检查初始化 | 上电预留约 100 ms，读 `0x603F`、`0x2202`、`0x2100:02` | 无故障、采样健康；校准完成值为 4 |
| 4. 首次校准 | 未校准时按 2.3 节校准并保存 | 校准状态 4，关桥、无故障 |
| 5. 配置参数 | 设置电流/Kt、通信、运动限值；需重启的参数先保存复位 | 重启后重新确认节点、速率和校准 |
| 6. 准备控制 | 选模式，初始化目标及完整 MIT 参数，配置 PDO 和周期 | 映射、单位、限值明确，持续发令循环已准备好 |
| 7. 网络运行 | NMT Start | Operational；压缩 MIT 还需先接收完整目标包 |
| 8. 驱动使能 | 控制字 `0x0006 → 0x0007 → 0x000F`，每步等状态 | 最终 `status & 0x006F = 0x0027` |
| 9. 持续控制 | 周期发目标/控制字，监测 TPDO 状态和故障 | 有效命令间隔 <100 ms，建议 5～20 ms |
| 10. 结束 | 按需 Halt、Quick stop 或直接关桥 | 直接关桥后回 Pre-operational、控制字 0 |

出厂 PDO 均禁用；**已保存的启用状态和映射会在重启后恢复**，不能假设每次上电都没有已启用 PDO。它们只有进入 Operational 后才处理，主站启动时应读取实际配置。

### 2.3 电角校准

向 `0x2100:01` 写 u32 `0x696C6163`，线上字节 `63 61 6C 69`（`cali`）。要求 Pre-operational、控制字 0、Switch-on disabled、无故障且零点采样完成。校准会施加 1.2 V 电压矢量并转动电机：对齐约 0.5 s、扫四个电周约 6 s、停稳约 0.5 s。

```sh
python3 tools/rollercan_cli.py nmt preop
python3 tools/rollercan_cli.py write 0x6040 0 u16 0
python3 tools/rollercan_cli.py write 0x2100 1 u32 0x696c6163
python3 tools/rollercan_cli.py read 0x2100 2 u8
```

| `0x2100:02` | 含义 | 处理 |
|---|---|---|
| 0 | required | 需要校准 |
| 1 / 2 / 3 | align / sweep / settle | 对齐、扫描、停稳计算中，继续等待 |
| 4 | complete | 成功，读结果并决定是否保存 |
| 5 | failed | 读故障、消除原因并复位后重新校准 |

轮询到 4 或 5，不应只固定延时就假定成功。校准是有界本地流程，无需周期重发请求；过程中不能重复请求或切 NMT Start。NMT Stop 会中止校准；控制字 0 本身不取消校准。中止后本次校准失效，须重新校准或复位加载先前保存的有效记录。

成功后读取 `0x2100:03` u16 极对数、`:04` i8 方向、`:05` f32 电角偏置 rad。结果立即供本次上电使用，跨复位保留须显式保存：

```sh
python3 tools/rollercan_cli.py read 0x2100 3 u16
python3 tools/rollercan_cli.py read 0x2100 4 i8
python3 tools/rollercan_cli.py read 0x2100 5 f32
python3 tools/rollercan_cli.py write 0x1010 1 u32 0x65766173
```

校准不辨识绕组参数、惯量、闭环增益或轴端力矩系数。电流上限 `0x2100:06`、Kt `:07` 修改后需要保存并重启才应用。

## 3. 驱动状态、公共限制与命令期限

### 3.1 控制字和状态字

| 状态 | `0x6041 & 0x006F` | 说明 |
|---|---|---|
| Switch-on disabled | `0x40` | 关桥，可开始使能 |
| Ready to switch on | `0x21` | 控制字 `0x0006` 后达到 |
| Switched on | `0x23` | 控制字 `0x0007` 后达到，尚未输出闭环功率 |
| Operation enabled | `0x27` | 控制字 `0x000F` 后达到，执行所选模式 |
| Quick stop active | `0x07` | 快速减速中，仍须发令 |
| Fault | `0x08` | 输出禁止，需显式复位 |

状态字含其他位，不能把完整值直接与 `0x27` 比较。位置模式 bit12 是新目标应答，bit10 是到位标志。

| `0x6040` 位 / 常用值 | 行为 |
|---|---|
| bit0/1/2/3 | 状态机命令，按 `6 → 7 → F` 握手 |
| bit1=0，例如 `0x0000` | 撤销电压许可，直接关桥 |
| `0x0007` / `0x0006`，从 enabled 写入 | 退回 switched-on / ready，停止功率输出 |
| bit2=0、bit1=1，例如 `0x000B` | 从 enabled 请求 Quick stop |
| bit4 | 两种位置模式的新目标触发，上升沿有效 |
| bit6 | 位置目标：0 绝对，1 相对当前实际位置 |
| bit7 | 故障复位，需新的 0→1 边沿 |
| bit8 | Halt，效果由模式决定 |

`0x6060` 是请求模式，`0x6061` 是实际模式，未使能时后者为 0。运行或 Quick stop 中改变 `0x6060` 会被拒绝，包括直接改模式 0。切换模式要先关桥、等 disabled，再设置模式和初始目标并重新握手。位置 bit5 的排队/立即切换细分未实现。

### 3.2 电流与力矩限制

设 `I_base` 为已应用的 `0x2100:06`，默认 0.25 A，可配置 `(0,0.5] A`。`Kt` 为已应用的 `0x2100:07`，范围 `(0.001,1] Nm/A`，默认约 0.04774648 Nm/A，为 KV 换算估值。

| 对象 | 类型 / 范围 | 含义 |
|---|---|---|
| `0x6072:00` | u16，0～1000，默认 1000 | 全局电流比例上限 |
| `0x2003:06` | u16，0～1000，默认 1000 | 非压缩格式附加比例上限 |
| `0x2004:0E` | u16，0～1000，默认 1000 | 压缩格式附加比例上限 |

当前实现按 `0x2004:01` 选择附加上限，并与全局上限取小值，**对所有运动模式均生效**：

```text
L = min(0x6072, 0x2004:01 ? 0x2004:0E : 0x2003:06)
I_max = I_base × L / 1000
```

切换到速度、位置、力矩或非压缩 MIT 时，应在关桥状态明确写 `0x2004:01=0`，避免遗留压缩设置影响限值和命令来源。比例 1000 不代表 1 A 或 1 Nm。输出另受电压矢量限制，目标电流与实际反馈不保证瞬时相等。

### 3.3 100 ms 命令期限

使能或 Quick stop 时，超过 100 ms 没有有效运动写入会锁存 `0x8130` 并关桥。`0x2100:08` 只读报告 100 ms。

- 普通模式：成功写 `0x6040`、`0x6071`、`0x607A`、`0x60FF` 或 `0x2003` 可写字段会刷新期限。主站应使用当前模式的目标/控制字续期。
- 压缩 MIT：仅完整且映射正确的压缩 RPDO 刷新期限，普通控制字、非压缩目标或 `0x2004:0E` 限值均不能为旧包续期。
- NMT、SYNC、Heartbeat、SDO 读取和格式错误的 RPDO 不刷新期限。

准备好周期循环后再使能，建议 5～20 ms。不能手工逐条 CLI 发令维持运行；Halt、Quick stop 时也须续期。该期限与 `0x140x:05` 的 RPDO 超时、`0x1016` 的心跳超时是不同机制。

## 4. PDO 映射与遥测配置

### 4.1 默认布局

下表列启用后的默认 ID；出厂通信对象带 bit31 禁用位。请读取当前配置，而不是假定设备仍处于出厂映射。

| PDO | 通信 / 映射索引 | 默认 ID | 依次排列的内容 | 字节数 |
|---|---|---|---|---:|
| RPDO1 | `1400` / `1600` | `0x200+N` | `60FF:00 f32` + `6040:00 u16` + `6060:00 i8` | 7 |
| RPDO2 | `1401` / `1601` | `0x300+N` | `607A:00 f32` + `6040:00 u16` + `6060:00 i8` | 7 |
| RPDO3 | `1402` / `1602` | `0x400+N` | `6071:00 i16` + `6040:00 u16` + `6060:00 i8` | 5 |
| RPDO4 | `1403` / `1603` | `0x500+N` | `2004:02 u32` + `2004:03 u32` | 8 |
| TPDO1 | `1800` / `1A00` | `0x180+N` | `603F:00 u16` + `6041:00 u16` + `6061:00 i8` | 5 |
| TPDO2 | `1801` / `1A01` | `0x280+N` | `6064:00 f32` + `606C:00 f32` | 8 |
| TPDO3 | `1802` / `1A02` | `0x380+N` | `6077:00 i16` + `2202:00 i32` | 6 |
| TPDO4 | `1803` / `1A03` | `0x480+N` | 无默认映射，使用前配置 | 0 |

映射项是 u32：`index << 16 | subindex << 8 | bit_length`，例如 `0x60FF0020`。权限和完整对象长度见 EDS，不要截取半个 Float32。`0x3000:01/02/03` 是可映射的 u8/u16/u32 占位对象，与 FD 自动填充字节不同。

### 4.2 重映射与传输类型

在 Pre-operational、控制字 0、关桥状态配置：

1. 读通信子索引 1，将 COB-ID bit31 置 1 禁用该 PDO，保留其他适用标志。
2. 将映射子索引 0 写 0。
3. 从子索引 1 起写完整映射项，最多 16 项、总长最多 64 B。
4. 将映射子索引 0 写为实际项数。
5. 配置通信子索引 2 的类型与相关 timer。
6. 清 COB-ID bit31 启用 PDO。空映射不是有效 PDO。
7. 需要跨复位保留则保存参数；进入 Operational 后周期通信。

RPDO 默认类型 255，收到后由 CANopen 任务应用；0～240 是同步接收，在 SYNC 边界处理。TPDO 默认类型 1，每个 SYNC 发送；1～240 每 N 个 SYNC 发送，类型 0 为有发送请求时在 SYNC 发送，254/255 为异步事件方式。241～253 不使用。

| 对象 | 单位 | 用途 |
|---|---|---|
| `0x140x:05` u16 | ms | RPDO 超时，0 禁用；接收开始后监测后续丢帧 |
| `0x180x:03` u16 | 100 µs | TPDO inhibit time，限制事件发送频率 |
| `0x180x:05` u16 | ms | TPDO event timer，0 不提供周期定时发送 |
| `0x1005:00` u32 | CAN ID / 标志 | SYNC COB-ID，默认 `0x80` |
| `0x1006:00` u32 | µs | SYNC 周期参数，默认 1000；同步控制时主站须实际发送 SYNC |
| `0x1007:00` u32 | µs | 同步窗口，默认 0 |

固定周期遥测应明确使用异步类型和非零 event timer，或按同步配置持续发送 SYNC；不能假定反馈变化必然触发所有 TPDO。周期应满足命令期限和总线负载要求。

例如配置速度 RPDO1 和每 20 ms 回传的长 TPDO4；配置命令会先关桥，不使能电机：

```sh
python3 tools/rollercan_cli.py pdo-map rpdo 1 0x60ff0020 0x60400010 0x60600008 --type 255
python3 tools/rollercan_cli.py pdo-map tpdo 4 0x603f0010 0x60410010 0x60610008 0x60640020 0x606c0020 0x22020020 --type 255 --event-ms 20
python3 tools/rollercan_cli.py pdo-list
```

该 TPDO4 有效 17 B、线上 20 B：故障 2 B、状态 2 B、模式 1 B、位置 4 B、速度 4 B、母线 4 B，补 3 B。Node 1 默认 ID 为 `0x481`；进入 Operational 后可用 `listen --id 0x481 --count 10 --seconds 2` 观察。

### 4.3 自动选择经典帧与 FD

| 有效映射长度 | 线上长度 | 格式 |
|---|---|---|
| 1～8 B | 同映射 | 经典 CAN |
| 9～12 / 13～16 / 17～20 B | 12 / 16 / 20 B | FD+BRS |
| 21～24 / 25～32 B | 24 / 32 B | FD+BRS |
| 33～48 / 49～64 B | 48 / 64 B | FD+BRS |

字段连续排列，无新增协议头。TX 填充为 0，RX 忽略填充值，但必须满足映射推导的最小合法线上长度。≤8 B 映射只接收等长经典帧；>8 B 映射只接收对应 DLC 的 FD 帧。错格式、短帧或更大 DLC 都被丢弃，不更新目标。SDO 等经典服务拒绝 FD 格式替代。

## 5. 速度与力矩控制

### 5.1 速度模式：`0x6060=3`

| 对象 | 范围 / 默认值 | 用途 |
|---|---|---|
| `0x60FF:00` f32 | -40～40 rev/s / 0 | 有符号目标速度 |
| `0x6083:00` f32 | `(0,100]` rev/s² / 2 | 加速度 |
| `0x6084:00` f32 | `(0,100]` rev/s² / 2 | 减速度 |
| `0x606C:00` f32 | rev/s | 实际速度 |

关桥、关闭压缩格式、选择模式 3，先把速度设为 0，配置限流和加减速度；进入 Operational 并完成握手后周期更新目标。默认 RPDO1 打包为 `struct.pack('<fHb', velocity, controlword, 3)`，7 B 经典帧。+0.1 rev/s、控制字 `0x000F` 的数据为 `CD CC CC 3D 0F 00 03`。

目标经斜坡限制进入速度 PI，PI 输出 Iq 目标，速度正负表示两个方向。正常减速到零可周期发送速度 0；Halt（例如 `0x010F`）也按减速度降至零，仍保持 enabled 和速度闭环，清 bit8 后恢复当前目标。完全关桥另发控制字 0 或 NMT Pre-operational。

### 5.2 力矩模式：`0x6060=4`

目标 `0x6071:00` 为 i16，范围 -1000～1000。反馈 `0x6077:00` 是测得 Iq 相对 `I_base` 的千分比；`0x6076:00` f32 表示 `I_base × Kt` 对应的估算 Nm。

```text
Iq_target = clamp(I_base × target_torque / 1000, -I_max, +I_max)
T_estimated = Kt × Iq
```

默认 0.25 A 上限下，目标 +100 对应 +0.025 A 的 Iq 目标、估算约 +0.001194 Nm；-100 反向。这不是有轴端力矩传感器的力矩反馈闭环。

关桥时选择模式 4、目标设为 0，完成握手后周期更新目标。默认 RPDO3 打包为 `struct.pack('<hHb', torque_per_mille, controlword, 4)`，5 B 经典帧；+100、`0x000F` 为 `64 00 0F 00 04`。此模式不使用速度加减速斜坡，目标直接进入电流环。Halt 将 Iq 目标置零并保持 enabled，解除后恢复当前目标；关桥另发停止命令。

## 6. 单圈与多圈位置控制

### 6.1 公共参数与目标握手

| 对象 | 范围 / 默认值 | 用途 |
|---|---|---|
| `0x607A:00` f32 | ±100000 rev / 0 | 绝对目标或相对位移 |
| `0x6081:00` f32 | `(0,40]` rev/s / 2 | 轨迹最大速度，必须为正 |
| `0x6083/6084:00` f32 | `(0,100]` rev/s² / 2 | 轨迹加/减速度 |
| `0x6065:00` f32 | `(0,100000]` rev / 0.25 | 轨迹参考与实际位置的跟随误差窗口 |
| `0x6066:00` u16 | ms / 1000；0 无额外等待 | 超出窗口持续时间，超过则故障 `0x8500` |
| `0x6064:00` f32 | rev | 累计实际位置 |

两个模式共用 RPDO2：`struct.pack('<fHb', position, controlword, mode)`，7 B 经典帧。配置轨迹参数和限流，将 bit4 保持为 0 完成使能。**只写 `0x607A` 不触发新运动**，须执行：

1. 周期发送 bit4=0（绝对 `0x000F`、相对 `0x004F`），等状态字 bit12 清零。
2. 写入/发送新目标，bit6 选择绝对或相对，再令 bit4 从 0 变 1（绝对 `0x001F`、相对 `0x005F`）。目标和触发位可在同一 RPDO 传输。
3. 等状态字 bit12 置 1，表示目标已接受。等待期间继续发送相同有效命令。
4. 保持 bit4=1 或清回 0 继续续期；清回 0 仅撤销应答，不取消已接受运动。下次新目标重新制造低→高边沿。

不要把低、高两帧在一个处理周期内紧邻发送后就假定边沿已被处理，应等待 bit12 的变化。相对目标只在边沿计算一次，持续发送相同 `0x005F` 不会不断累加；反复翻转 bit4 则会发出多次目标。

轨迹依据加减速度、制动距离和最大速度运动，位置误差经速度环转换成电流。到位判据为 `|已接受目标 - 实际位置| < 0.001 rev` 且 `|实际速度| < 0.05 rev/s`，满足时 bit10 置位。bit12 是“已接受”，不能代替“已到位”。

Halt 按减速度把轨迹速度降到零，保持停止时的轨迹参考位置；清除后继续前往已接受目标。运行中接受的新目标替换旧目标，不提供排队缓存。

### 6.2 单圈最短路径：`0x6060=-1`

模式为 i8，-1 在线上编码为 `0xFF`。触发时目标转换为离当前位置最近的等效累计位置：

```text
delta = relative ? target : target - current_position
delta_short = delta - floor(delta + 0.5)       # [-0.5, 0.5)
accepted_target = current_position + delta_short
```

- 绝对目标：当前位置 0.95 rev，目标 0.05 rev，正转约 0.10 rev。
- 相对目标：+0.75 rev 按最短路径解释为 -0.25 rev。
- 恰半圈统一走负方向；已接受目标不随实时位置重新取模而跳圈。

关桥时选模式 -1，随后按公共位置握手发目标。此模式用于机械角度定位；明确需要大于半圈的位移应使用多圈模式。`0x6064` 仍返回累计位置。

### 6.3 多圈累计位置：`0x6060=1`

模式 1 不取模。bit6=0 时目标是当前上电坐标中的绝对累计位置；bit6=1 时目标为触发瞬间实际位置加上传入位移。

当前位置 0.25 rev 时，绝对目标 2.50 rev 与相对目标 +2.25 rev 都得到 2.50 rev；相对目标 -1.50 rev 得到 -1.25 rev。设置轨迹速度与加减速度后，按 6.1 节触发并等待应答。

CLI 的 `mode position` 和 `mode multi-turn` 均选模式 1，`mode single-turn` 选 -1。这些命令只写模式，不执行使能握手或发送目标。

## 7. MIT 控制

### 7.1 控制公式与坐标

模式 `0x6060=5`，计算：

```text
T = T_ff + Kp × (p_cmd - p_actual) + Kd × (v_cmd - v_actual)
Iq_target = clamp(T / Kt, -I_max, +I_max)
```

位置单位 rev、速度 rev/s、力矩 Nm；Kp 为 Nm/rev，Kd 为 Nm/(rev/s)。MIT 使用累计位置误差，不做单圈最短路径，也不经过 `0x6081/6083/6084` 轨迹。Halt 将 Iq 目标置零，清除后按当前目标重新计算。

MIT 的 Kp/Kd 是输出力矩公式的增益，与内部电流 PI、速度 PI 增益不是同一组参数。原主站若使用 rad，应转换位置、速度和增益：`p_rev=p_rad/(2π)`、`v_rev_s=v_rad_s/(2π)`，对应 `Kp_rev=2π×Kp_rad`、`Kd_rev=2π×Kd_rad`。

### 7.2 非压缩 MIT：对象与尺度因子

关桥时先写 `0x2004:01=0`，然后完整初始化：

| 对象 | 类型 | 范围 / 默认值 | 含义 |
|---|---|---|---|
| `0x2003:01` | f32 | ±100000 rev / 0 | 累计位置目标 |
| `0x2003:02` | f32 | ±40 rev/s / 0 | 速度目标 |
| `0x2003:03` | f32 | ±1 Nm / 0 | 前馈力矩 |
| `0x2003:04` | u16 | 0～65535 / 0 | Kp 原始值 |
| `0x2003:05` | u16 | 0～20000 / 0 | Kd 原始值 |
| `0x2003:06` | u16 | 0～1000 / 1000 | 附加电流比例上限 |
| `0x2003:07` | f32，只读 | 固定 0.001 | Kp、Kd 共用尺度因子 |

```text
Kp_actual = 0x2003:04 × 0.001       # 0～65.535 Nm/rev
Kd_actual = 0x2003:05 × 0.001       # 0～20 Nm/(rev/s)
```

Kp/Kd 分别可调，但共用一个只读尺度因子，不是两个分别可写的尺度对象。例如原始值 50、5 对应 0.05、0.005。前馈力矩直接为 Float32 Nm，不再乘该因子。

为平滑开始，可将当前累计位置作为初始 `p_cmd`、速度和前馈力矩设为 0，使能前完成增益初始化。运行中的多次 SDO 写入分别生效，不构成一条原子 MIT 指令。推荐使用一个长 RPDO：

```sh
python3 tools/rollercan_cli.py nmt preop
python3 tools/rollercan_cli.py write 0x6040 0 u16 0
python3 tools/rollercan_cli.py write 0x2004 1 u8 0
python3 tools/rollercan_cli.py pdo-map rpdo 4 0x20030120 0x20030220 0x20030320 0x20030410 0x20030510 0x60400010 0x60600008 --type 255
```

该映射 19 B、线上 20 B FD+BRS；Node 1 默认 ID 为 `0x501`。

| 偏移 | 字段 |
|---|---|
| 0～3 / 4～7 / 8～11 | p_cmd / v_cmd / T_ff，各 f32 |
| 12～13 / 14～15 | Kp / Kd 原始值，各 u16 |
| 16～17 | controlword u16 |
| 18 | mode i8，值 5 |
| 19 | FD 填充，不属于映射 |

主站打包：

```python
payload = struct.pack('<fffHHHb', p_cmd, v_cmd, torque_ff, kp_raw, kd_raw, controlword, 5)
send_frame(sock, 0x501, payload)  # 自动补零为 20 B FD+BRS
```

进入 Operational 后，可用完整帧分别携带控制字 6、7、15 握手，随后持续发送运行帧；如果用 SDO 使能，先写好全部 MIT 参数，握手完成立即进入周期发送。需同帧更新附加上限时，可加入 `0x20030610`，成为 21 B 有效数据、24 B 线上帧；主站打包顺序也要同步调整。

### 7.3 压缩 MIT：8 字节经典 CAN

仍选模式 5，通过 `0x2004:01=1` 选择压缩格式。必须存在且只能存在一个有效 RPDO 包含压缩字段，并且严格按顺序仅映射 `0x20040220`、`0x20040320`。不能跨 PDO、重复映射或往此 PDO 附加控制字；其他不包含压缩字段的 PDO 可以存在。

```text
63              48 47        36 35        24 23        12 11         0
| position 16 bit | velocity 12 | Kp 12      | Kd 12      | torque 12   |
```

u64 按小端发送：`0x2004:02` 是低 32 位、先发，`:03` 是高 32 位、后发。字段为无符号整数，线性映射到物理量：

```text
physical = min + unsigned_value × (max - min) / (2^bits - 1)
```

| 物理量 | 位数 | min / max 对象 | 默认范围 | 可配置边界 |
|---|---:|---|---|---|
| 位置 | 16 | `0x2004:04 / :05` | -0.5～0.5 rev | ±100000 rev |
| 速度 | 12 | `:06 / :07` | -10～10 rev/s | ±40 rev/s |
| Kp | 12 | `:08 / :09` | 0～100 Nm/rev | 0～100 |
| Kd | 12 | `:0A / :0B` | 0～20 Nm/(rev/s) | 0～20 |
| 前馈力矩 | 12 | `:0C / :0D` | -0.05～0.05 Nm | ±1 Nm |

范围必须有限、min < max，并在停止状态修改。当前累计位置若超出默认 ±0.5 rev，先调整范围再编码。**压缩增益直接按 min/max 换算，不乘非压缩格式的 0.001 因子。**量化可能使物理零值只能近似表示，范围越宽分辨率越低。

主站编码示例，输入须为有限值且在范围内：

```python
import math

def quantize(x, low, high, bits):
    if not all(math.isfinite(v) for v in (x, low, high)) or not low <= x <= high or not low < high:
        raise ValueError('MIT value/range invalid')
    return round((x - low) / (high - low) * ((1 << bits) - 1))

# 各 q 值按上表相应范围与位数计算。
word = (p_q << 48) | (v_q << 36) | (kp_q << 24) | (kd_q << 12) | torque_q
payload = struct.pack('<Q', word)  # 低 32 位先发，恰好 8 B 经典帧
```

完整启动顺序：关桥并写压缩开关 0 → 配置唯一合法压缩 RPDO → 设置范围和 `0x2004:0E` 上限 → 选择模式 5 → 压缩开关写 1 → NMT Start → **先周期发送完整目标包** → 再通过独立 SDO 或不含压缩字段的控制字 RPDO 执行 `6 → 7 → F` 握手。

首个完整帧到达前固件屏蔽运行控制字，仅保留 bit7 故障复位。使能后持续发压缩帧，控制字、Halt、Quick stop 走独立通道，不能替代完整包续期。

离开 Operational、切换模式、修改压缩开关或量化范围会使旧包失效，重新使能前须收到新完整帧。改映射前先关闭压缩开关；压缩模式启用时禁止用 SDO 写 `:02/:03` 拼接目标。`:0E` 允许运行中调整，立即参与限流，不使旧包失效但不刷新期限。格式开关、量化范围和附加限值不跨重启恢复，每次启动均应明确配置。

## 8. 周期主站示例

以下是完整的低速运行示例，**执行会驱动电机**。前提是已按第 2 节初始化与校准；示例使用 Node 1、`0x201`，将 RPDO1 配为速度布局。脚本执行握手、周期发送、状态检查，退出时撤销使能；实际应用仍需自己的周期调度。

```python
import struct
import sys
import time
sys.path.insert(0, 'tools')
from rollercan_cli import SdoClient, send_frame

def wait_state(client, expected):
    deadline = time.monotonic() + 0.08
    while True:
        status = client.read(0x6041, 0, 'u16')
        if status & 0x006F == expected:
            return
        if status & 0x0008 or time.monotonic() >= deadline:
            raise RuntimeError(f'Drive state: {status:#06x}')
        time.sleep(0.002)

with SdoClient('can0', 1) as client:
    try:
        client.preoperational_disabled()
        if client.read(0x603F, 0, 'u16') != 0:
            raise RuntimeError('Clear the fault cause and reset explicitly')
        if client.read(0x2100, 2, 'u8') != 4:
            raise RuntimeError('Calibration required')
        client.write(0x2004, 1, 'u8', 0)
        client.write(0x6060, 0, 'i8', 3)
        client.write(0x60FF, 0, 'f32', 0.0)
        cfg = client.map_pdo('rpdo', 1,
                             [0x60FF0020, 0x60400010, 0x60600008],
                             cob_id=0x201, transmission_type=255, timeout_ms=0)
        client.nmt(1)
        for controlword, expected in [(6, 0x21), (7, 0x23), (15, 0x27)]:
            client.write(0x6040, 0, 'u16', controlword)
            wait_state(client, expected)

        deadline = time.monotonic() + 2.0
        while time.monotonic() < deadline:
            send_frame(client.socket, cfg['cob_id'], struct.pack('<fHb', 0.1, 15, 3))
            if client.read(0x6041, 0, 'u16') & 0x006F != 0x27:
                raise RuntimeError('Drive left Operation enabled')
            time.sleep(0.01)
    finally:
        client.nmt(2)
        client.preoperational_disabled()  # 恢复 SDO 服务并写控制字 0
```

换模式时按第 5～7 节替换映射、参数和载荷，不能只改最后一个模式字节。`pdo-send` 每次先用 SDO 查映射，适合单帧检查；周期运动应只配置/读取一次映射，然后直接 `send_frame`。TPDO 接收使用独立的 `open_can_socket('can0', filters=[ID])`，`recv_frame` 返回 `is_fd/brs/esi` 及线上数据；SDO 客户端 socket 只订阅本节点 SDO 回复。

## 9. 停止、故障与恢复

### 9.1 停止语义

| 动作 | 结果 | 许可与续期 |
|---|---|---|
| Halt，bit8=1 | 位置减速并保持轨迹参考；速度减速到零；力矩/MIT 的 Iq 目标置零 | 仍 enabled、仍须续期；清 bit8 恢复当前目标 |
| Quick stop，常用 `0x000B` | 速度闭环按 `0x6085` 减速；速度绝对值小于 0.05 rev/s 后 disabled | 减速时续期，结束后重新握手 |
| 控制字 0、NMT Stop / Pre-operational | 直接禁止功率输出，不软减速、不保持位置 | 自由滑行，重新运行需握手 |

`0x6085:00` f32 默认 4 rev/s²，范围 `(0,100]`。Quick stop 在所有模式使用相同速度减速路径。`0x605A/605B/605C/605E/6007` 只读报告已实现的策略，不能用于选择其他停止行为。

### 9.2 驱动故障与 SDO Abort

`0x603F:00` u16 报告驱动故障，状态字 fault 位同时置位、输出禁止。协议错误还可从 EMCY、`0x1001` 错误寄存器、`0x1003` 历史记录观察；EMCY 的 CANopen 错误码不一定等于驱动故障码。

| 驱动故障码 | 含义 |
|---|---|
| `0x0000` | 无故障 |
| `0x2310` | 相电流超过 0.75 A |
| `0x3210` / `0x3220` | 母线高于 16 V / 低于 4.5 V |
| `0x4210` | MCU 内温达到 85 °C |
| `0x5000` | 驱动故障输入或用户按钮 |
| `0x5300` | 控制时序或任务监督异常 |
| `0x6320` | 非法配置、采样或运动命令 |
| `0x7340` | 编码器通信、CRC 或角度异常 |
| `0x8130` | 通信、命令期限或相关任务健康异常 |
| `0x8312` | 电角校准失败 |
| `0x8500` | 位置跟随误差超时 |

SDO Abort 表示某次对象访问失败，不等同于驱动已经 fault。主站应报告索引、子索引、原始 abort code，并检查只读写入、错误长度、非法映射、超范围或状态条件不满足等原因，避免无条件重试。

| 常见 SDO Abort | 含义 / 优先检查 |
|---|---|
| `0x06010002` | 写入只读对象，例如 MIT 尺度因子或 BRS |
| `0x06040041` | 对象不能映射或压缩 MIT 的完整映射要求不满足 |
| `0x06040042` | PDO 映射总长度超限 |
| `0x06070010` | 数据类型/长度不匹配 |
| `0x06090030` | 参数值非法或超出允许范围 |
| `0x08000022` | 当前状态不允许操作，例如运行中变速或保存 |

RPDO 无 SDO 式错误回复。格式/长度不匹配的帧被丢弃；格式正确但含 NaN、非法字段或运行中切模式时，会锁存配置故障，并禁止执行该批部分更新的运动目标。

### 9.3 恢复流程

1. 停止主站运动发送循环，发 NMT Pre-operational、控制字 0。
2. 读 `0x603F` 和反馈，消除物理/配置原因，不能直接重发 `0x000F` 期望恢复。
3. 确认 bit7 已为 0，再通过 **SDO** 写 `0x6040=0x0080`，轮询 fault 清除。该写入也解除非法 PDO 的协议拒收锁。
4. 写控制字 0，确认 disabled；校准失效时重新校准。重新准备目标与周期循环，再 Start 和完整握手。

复位要求编码器、ADC、驱动输入、母线、温度和通信恢复健康，且相电流低于 0.1 A。持续保持 bit7=1 不产生第二次复位；总线恢复不会自动清故障或重启运动。

RX/TX 队列溢出锁存须 NMT Reset 重新初始化。Bus-off 会尝试恢复 CAN 控制器，但电机仍保持故障态。Heartbeat consumer 默认关闭，`0x1016:01` u32 支持一个被监测主站，格式 `(node_id << 16) | timeout_ms`，例如节点 5、100 ms 为 `0x00050064`；收到首次心跳后开始监测。心跳丢失影响网络运行许可，不替代运动命令期限。

## 10. 通信参数、保存与恢复默认

### 10.1 Node-ID 与波特率

| 对象 | 类型 | 可设值 |
|---|---|---|
| `0x2001:01` | u8 | Node-ID 1～127 |
| `0x2001:02` | u32，bit/s | 仲裁段 125000 / 250000 / 500000 / 1000000 |
| `0x2001:03` | u32，bit/s | 数据段 1000000 / 2000000 / 4000000 / 5000000 / 8000000 |
| `0x2001:04` | u8，只读 | BRS=1 |

统一在 Pre-operational、关桥、控制字 0、没有进行校准时修改。写入仅更改待应用值，当前 SDO 应答仍使用旧节点和旧速率；保存后重启应用。读对象得到的是待应用配置，不是已在线切换的确认。改 Node-ID 后应重新检查 PDO COB-ID，特别是自定义或已保存的 ID，不应只按默认公式推断。

```sh
# 设置并保存，仍使用当前速率
python3 tools/rollercan_cli.py can-config --nominal 500k --data 2m --save
python3 tools/rollercan_cli.py nmt reset
# 设备重启使用新速率，主站同步调整
sudo ip link set can0 down
sudo ip link set can0 type can bitrate 500000 dbitrate 2000000 fd on
sudo ip link set can0 up
python3 tools/rollercan_cli.py inspect
```

`can-config --save --reset` 可连续完成保存和复位，但不修改主机 can0。只写不保存，复位恢复上次保存值；变速后仍保持关桥，主站重新执行初始化检查。

### 10.2 保存范围与生效时机

向 `0x1010:01` 写 u32 `0x65766173`（线上 `73 61 76 65`，`save`）显式保存，要求非运行、控制字 0、实际功率桥关闭。推荐统一在 Pre-operational、校准完成后保存。

| 类别 | 重启恢复行为 |
|---|---|
| 电角校准、极对数、方向、偏置 | 恢复已保存结果；校准成功不自动保存 |
| `0x2100:06/:07` 电流上限、Kt | 写入暂存，保存并重启后应用 |
| `0x2001` Node-ID、仲裁/数据速率 | 保存并重启应用 |
| SYNC、EMCY、Heartbeat 配置 | 保存后恢复 |
| PDO COB-ID、映射、类型和 timer | 保存后恢复，包括启用状态 |
| `0x6065/6066`、`0x6072`、`0x6081/6083/6084/6085` | 保存后恢复跟随窗口、全局上限和轨迹参数 |
| 控制字、模式、目标、`0x2003`、`0x2004`、校准请求 | 不恢复运行命令；MIT 增益、范围、开关及附加上限需主站重新设置 |

双页 Flash 记录使用 CRC 和最后提交标记。新布局为 v2，可迁移旧 v1 校准、Node-ID、PDO 和原持久化参数；旧版只读通信常量迁移为默认 1M/5M/BRS=1，首次加载不自动写 Flash。烧录时保留最后 4 KiB 参数区，详见 [构建说明](build.md)。

### 10.3 恢复默认

关桥后向 `0x1011:01` 写 u32 `0x64616F6C`（线上 `6C 6F 61 64`，`load`），把默认参数保存为下次启动配置，当前 RAM 不立即全部切换。随后复位或重新上电，回到 Node 1、1M/5M、默认禁用 PDO 和未校准状态。**恢复默认会使已保存校准失效**，下次运行须重新校准。

## 11. 反馈对象与主站集成检查

| 对象 | 内容 / 注意点 |
|---|---|
| `0x6041`、`0x603F`、`0x6061` | 实际状态、故障、实际模式，宜纳入周期遥测 |
| `0x6064`、`0x606C` | 累计位置、实际速度，f32 |
| `0x6077` | 实测 Iq 的有符号千分比，瞬态可能超过目标比例 |
| `0x2200:01/02/03` | A/B/C 相电流 mA |
| `0x2203:01/02` | Id / Iq 电流 mA |
| `0x2201:01/02/03` | 按占空比推算的相电压 mV，不是电压传感器；关桥为 0 |
| `0x2202:00` | 母线电压 mV |
| `0x2100:09` | MCU 内温，不是电机或驱动器温度 |
| `0x2100:0A` | ADC DMA 帧回调入口至本帧控制和输出结束的历史最大 DWT 周期数，包含此后尚未完成的 SSC 等待及中断延迟，160 cycles=1 µs |

集成时确认节点与速率、初始化和校准、实际 PDO 映射与格式、使能握手、位置 bit4/bit12 应答、MIT 单位及尺度、命令周期、停止和故障恢复。EDS 描述布局，本文描述行为；两者以当前源码为准。变更对象时修改 `tools/generate_od.py`，重新生成 OD、EDS 和对象索引文档。
